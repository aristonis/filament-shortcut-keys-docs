# الإعدادات

## مقدّمة

تعمل الإضافة من دون ملف إعدادات. لتغيير قيمة افتراضية، انشر الملف:

```bash
php artisan vendor:publish --tag="filament-shortcut-keys-config"
```

يُنشئ هذا الأمر `config/shortcut-keys.php`. وتنطبق الخيارات على كل لوحة تسجّل الإضافة. والاستثناء هو إجراءات الصفوف: فأنت [تسجّلها على الإضافة](row-actions.md#registering-row-actions)، لكل لوحة على حدة.

تقرأ الإضافة الإعدادات في كل عرض للصفحة، فيسري التغيير من الطلب التالي. وإذا كان تطبيقك يخزّن إعداداته مؤقتًا، فشغّل `php artisan config:cache` مرة أخرى بعد تغيير الملف.

## ملف الإعدادات

يحتوي الملف المنشور على هذه الخيارات وقيمها الافتراضية:

```php
return [

    'customization' => 'personal',

    'modifiers' => [
        'navigation' => ['g'],
        'global' => [],
        'table' => [],
        'row-action' => [],
        'custom' => ['g'],
    ],

    'authorize' => null,

    'overlay' => [],

    'cache' => [
        'ttl' => 86400,
    ],

];
```

## اختيار وضع التخصيص

الخيار `customization` إمّا `'personal'`، وهو الافتراضي، وإمّا `'locked'`:

```php
'customization' => 'locked',
```

انظر [اختيار وضع التخصيص](customization.md#choosing-a-customization-mode).

## تغيير طريقة ضغط المفاتيح

يضبط الخيار `modifiers` طريقة ضغط مفاتيح كل مجموعة. والمجموعات هي `navigation`، و`global` (إجراءات الترويسة)، و`table`، و`row-action`، و`custom` (الروابط المخصّصة). وتأخذ كلٌّ منها قائمة من الرموز (`tokens`):

| القيمة | المعنى |
| --- | --- |
| `['g']` | مفتاح بادئة: اضغط `G`، وارفع إصبعك عنه، ثم اضغط الحرف. ويصلح أي حرف صغير واحد. |
| `[]` | مفاتيح مفردة، من دون مفتاح تعديل |
| `['alt']`، `['ctrl', 'shift']`، ... | مفاتيح تُضغط مع الإمساك بمفاتيح التعديل. والرموز هي `ctrl` و`alt` و`shift` و`meta`. |

`meta` هو مفتاح `Cmd` على Mac ومفتاح Windows على Windows. وتعرضه ورقة الاختصارات باسم `Cmd`.

مثلًا، لوضع إجراءات الترويسة على `Alt` ومنح الروابط المخصّصة مفتاح بادئة خاصًا بها هو `H`:

```php
'modifiers' => [
    'navigation' => ['g'],
    'global' => ['alt'],
    'table' => [],
    'row-action' => [],
    'custom' => ['h'],
],
```

تتجنّب القيم الافتراضية مفاتيح التعديل الممسوكة عن قصد. انظر [الاختصارات](shortcuts.md#introduction).

تنطبق هذه القواعد:

- **إزالة مجموعة من القائمة تعيد قيمتها الافتراضية.** ولا تحوّل المجموعة إلى مفاتيح مفردة، لذا فحذف سطر طريقة آمنة للتراجع عن تغيير.
- **المجموعات ذات الإعداد نفسه تتشارك مجمّعًا واحدًا من الأحرف**، فلا تحصل أبدًا على المفتاح نفسه. افتراضيًا، يتشارك التنقّل والروابط المخصّصة مجمّع `G`، وتتشارك إجراءات الترويسة وإجراءات الصفوف مجمّع المفاتيح المفردة.
- **مفتاح البادئة محجوز بين المفاتيح المفردة**، فلا يأخذه أي اختصار أحادي المفتاح.
- **المخطّط واحد لكل المشرفين.** لا يوجد إعداد لكل مشرف على حدة.

لا يوجد رمز `mod`. فكونه يعني `Ctrl` أو `Cmd` يتوقّف على منصّة المشرف، بينما تُبنى خريطة المفاتيح على الخادم.

### الإعدادات غير الصالحة

ترمي هذه الإعدادات استثناءً عند عرض صفحة من اللوحة، برسالة تسمّي المشكلة:

| الخطأ | مثال |
| --- | --- |
| رمز غير معروف | `['option']`، أو `['mod']`، أو مفتاح بادئة بحرف كبير مثل `['G']` |
| مفتاح بادئة مقترن برموز أخرى | `['g', 'shift']` |
| مفتاح بادئة على مفتاح جدول مفرد | `'navigation' => ['j']` بينما مفاتيح الجدول مفاتيح مفردة |
| إجراءات الترويسة أو إجراءات الصفوف على الإعداد نفسه الذي يستخدمه التنقّل أو الروابط المخصّصة | `'global' => ['g']`، أو `'row-action' => []` مع `'navigation' => []` |

توجد القاعدة الأخيرة لأنّ هاتين الفئتين تُعطيان أحرفهما كلٌّ على حدة، فقد يعطي المجمّع المشترك مفتاحًا واحدًا لاختصارين. ويجوز أن يكون لإجراءات الترويسة وإجراءات الصفوف مفتاح بادئة خاص بها، مثل `'global' => ['a']`.

## تخويل مؤلّفي الإعدادات المسبقة

يحدّد الخيار `authorize` من يحقّ له إنشاء الإعدادات المسبقة المشتركة للوحة وتعديلها. ويقبل `null`، الذي يرفض الجميع وهو الافتراضي، أو اسم قدرة في `gate`، أو دالة `closure`:

```php
'authorize' => 'manage-shortcut-keys',
```

تتلقّى الدالة `closure` الوسيطين `?Authenticatable $user` و`string $panelId`، ويجب أن تُرجع `true` تمامًا لمنح الوصول. فضّل قدرة `gate`، لأنّ الدالة `closure` تمنع `php artisan config:cache` من العمل. انظر [منح صلاحية التأليف](customization.md#granting-authoring-access).

## تثبيت الاختصارات وتعطيلها

يثبّت الخيار `overlay` اختصارًا على حرف أو يزيله، من الكود ولكل المشرفين:

```php
'overlay' => [
    'navigation:App\Filament\Resources\ProductResource' => ['letter' => 'p'],
    'global:export' => ['letter' => 'x'],
    'row-action:approve' => ['letter' => 'a'],
    'navigation:App\Filament\Pages\Settings' => ['disabled' => true],
    'table:delete' => ['disabled' => true],
],
```

كل مفتاح يسمّي اختصارًا بالصيغة `set:name`:

| المجموعة | الاسم | مثال |
| --- | --- | --- |
| `navigation` | صنف المورد أو الصفحة | `navigation:App\Filament\Resources\OrderResource` |
| `global` | اسم إجراء الترويسة | `global:export` |
| `row-action` | اسم إجراء الصف المسجّل | `row-action:approve` |
| `table` | [اسم مفتاح جدول](table-shortcuts.md#turning-off-a-table-key) | `table:delete` |

كل قيمة واحدة ممّا يلي:

- `['letter' => 'r']`، التي تضع الاختصار على ذلك الحرف،
- `['disabled' => true]`، التي تزيل الاختصار وتحرّر حرفه للآخرين.

تثبيت حرف يمنح أيضًا مفتاحًا لإجراء ترويسة [يعمل فورًا](shortcuts.md#which-header-actions-get-a-shortcut)، لا يملك مفتاحًا لولا ذلك. فلا تثبّت حرفًا لمثل هذا الإجراء إلا إذا كان تشغيله بضغطة عَرَضية أمرًا مقبولًا.

الحرف المثبّت الواقع خارج النطاق من `a` إلى `z`، أو على مفتاح محجوز في مجمّعه (`G` أو `J` أو `K` بين المفاتيح المفردة)، يُتجاهَل، فلا يستطيع إدخال خاطئ واحد أن يكسر خريطة المفاتيح. والروابط المخصّصة تخصّ المشرف ولا يمكن تثبيتها أو تعطيلها هنا.

الـ `overlay` مخصّص للمفاتيح التي تحتاج إلى تثبيتها في الكود، لا للتفضيلات. والتعطيل في الـ `overlay` يتجاوز أيضًا تغيير المشرف نفسه، لكنّ المشرف الذي يعيد تعيين اختصار مثبّت يحصل على حرفه هو. انظر [كيف تتجمّع التغييرات](customization.md#how-changes-combine).

!!! tip
    يمكن أن تتعارض الأحرف المثبّتة فيما بينها. بعد إضافة تثبيتات، افتح ورقة الاختصارات وتحقّق من أنّ كل اختصار مثبّت ما زال يملك مفتاحه.

## التخزين المؤقت

اختصارات التنقّل والروابط المخصّصة متماثلة في كل صفحة، لذلك تخزّنها الإضافة مؤقتًا في مخزن الـ `cache` الافتراضي لتطبيقك. ويضبط الخيار `cache.ttl` المدة، بالثواني، التي تُحفَظ فيها خريطة المفاتيح المخزّنة مؤقتًا:

```php
'cache' => [
    'ttl' => 86400,
],
```

لا تحتاج إلى مسح الـ `cache` عندما يتغيّر شيء. فإضافة مورد أو صفحة أو إزالتهما أو إعادة تسميتهما أو إعادة ترتيبهما، وحفظ تغيير في صفحة **Manage shortcuts**، وتعديل الخيارين `overlay` أو `modifiers`، وتبديل اللغة (`locale`)، كلٌّ منها يستخدم مُدخلًا جديدًا في الـ `cache` تلقائيًا. والمشرفون الذين يستخدمون الخريطة نفسها يتشاركون مُدخلًا واحدًا.

لا تُحذف المُدخلات القديمة، ومدة الصلاحية هي ما يزيلها. اضبط `ttl` على `null` للتخزين المؤقت إلى الأبد. ولا تفعل ذلك إلا على مخزن `cache` تديره بنفسك، لأنّ المُدخلات القديمة تتراكم حينئذٍ مع كل تغيير يجريه مشرفوك.
