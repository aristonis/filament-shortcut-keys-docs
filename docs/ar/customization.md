# السماح للمشرفين بالتخصيص

## مقدّمة

إعدادان منفصلان يتحكّمان في من يحقّ له تغيير الاختصارات:

- الخيار `customization` يحدّد هل يحقّ لكل مشرف تغيير مفاتيحه **هو**. ولا يمسّ أحدًا غيره أبدًا.
- الخيار `authorize` يحدّد من يحقّ له تعديل **الإعدادات المسبقة المشتركة** واختيار الإعداد المسبق الافتراضي للوحة. وهو يرفض الجميع افتراضيًا، وكون المستخدم مشرفًا لا يمنحه هذه الصلاحية.

يوجد الخياران كلاهما في `config/shortcut-keys.php`. انظر [نشر ملف الإعدادات](installation.md#publishing-the-configuration).

<a id="choosing-a-customization-mode"></a>

## اختيار وضع التخصيص

اضبط الخيار `customization` على `personal` أو `locked`:

```php
'customization' => 'personal',
```

<a id="personal-mode"></a>

### الوضع الشخصي

`personal` هو الوضع الافتراضي. يستطيع كل مشرف فتح صفحة **Manage shortcuts**، والاختيار بين الإعدادات المسبقة التي تنشرها، وإعادة تعيين اختصارات التنقّل الخاصة به وتعطيلها، وإضافة [روابط مخصّصة](custom-bindings.md).

### الوضع المقفل

`locked` يوقف التعديل الشخصي:

```php
'customization' => 'locked',
```

يستخدم المشرفون الإعداد المسبق الافتراضي للوحة، الذي يضبطه مشرف مخوَّل في صفحة **Manage shortcuts**. وعندما لا يكون هناك افتراضي مضبوط، يحصلون على الاختصارات التلقائية.

والمشرف الذي كان لديه اختيار عندما حوّلت اللوحة إلى `locked`، سواء كان إعدادًا مسبقًا اختاره أو خريطة شخصية، يحتفظ به ولا يعود قادرًا على تغييره.

في وضع `locked`، لا يستطيع فتح صفحة **Manage shortcuts** إلا المشرفون الذين يجتازون [بوابة التأليف](#granting-authoring-access).

## صفحة Manage shortcuts

في وضع `personal`، يرى كل مشرف هذه الإجراءات في صفحة **Manage shortcuts**:

| الإجراء | ما يفعله |
| --- | --- |
| Change active map | التبديل إلى أحد الإعدادات المسبقة للوحة، أو العودة إلى "Your customizations" |
| Remap a shortcut | وضع اختصار تنقّل على حرف آخر |
| Disable a shortcut | إزالة اختصار تنقّل |
| Reset to default | إزالة تغييرك على اختصار واحد |
| Add custom binding | ربط مفتاح بصفحة في التطبيق أو بعنصر في الصفحة. انظر [الروابط المخصّصة](custom-bindings.md). |

لا تعرض الصفحة إلا اختصارات التنقّل. أمّا مفاتيح إجراءات الترويسة والجدول وإجراءات الصفوف فيغيّرها مطوّر عبر [الـ `overlay`](configuration.md#pinning-and-disabling-shortcuts).

الحرف الواقع خارج النطاق من `a` إلى `z` يُتجاهَل، ويحتفظ الاختصار بالحرف الذي كان سيحصل عليه لولا ذلك.

## كيف تعمل الخرائط الشخصية

لا يعدّل المشرف أبدًا إعدادًا مسبقًا مشتركًا. فأول تغيير له ينسخ الخريطة التي يستخدمها حاليًا، سواء كانت الإعداد المسبق الذي اختاره أو الافتراضي للوحة، إلى خريطة شخصية، ويختارها، ويحفظ التغيير فيها. ويبقى الإعداد المسبق نفسه من دون تغيير.

لا تخزّن الخريطة الشخصية إلا تغييرات المشرف. وكل ما لا تذكره يحتفظ باختصاره التلقائي، فالمورد الذي تضيفه الشهر القادم يحصل على مفتاح في خريطة خصّصها مشرف اليوم.

النسخ يحدث مرة واحدة. والتغييرات اللاحقة على الإعداد المسبق الذي جاءت منه الخريطة الشخصية لا تصل إليها. **Reset to default** يزيل تغيير المشرف، فيعود الاختصار إلى حرفه التلقائي، لا إلى حرف الإعداد المسبق. وللعودة إلى إعداد مسبق بالكامل، يختاره المشرف عبر **Change active map**. وتبقى خريطته الشخصية في القائمة لوقت لاحق.

## منح صلاحية التأليف

يسمح التأليف للمشرف بإنشاء الإعدادات المسبقة المشتركة وتعديلها واختيار الإعداد المسبق الافتراضي للوحة. امنحه عبر الخيار `authorize`، إمّا باسم قدرة (`ability`) في [`gate`](https://laravel.com/docs/authorization#gates) وإمّا بدالة `closure`.

نوصي بقدرة `gate`. عرّفها في مزوّد خدمة (`service provider`). وتتلقّى القدرة معرّف اللوحة (`panel ID`) وسيطًا لها:

```php
use App\Models\User;
use Illuminate\Support\Facades\Gate;

public function boot(): void
{
    Gate::define('manage-shortcut-keys', function (User $user, string $panelId): bool {
        return $user->is_developer;
    });
}
```

ثم اذكر اسم القدرة في ملف الإعدادات:

```php
'authorize' => 'manage-shortcut-keys',
```

تُفحَص القدرة على هذا النحو: `Gate::forUser($user)->allows('manage-shortcut-keys', $panelId)`. والزائر غير المسجّل دخوله يُرفَض قبل سؤال الـ `gate`. واستدعاء `Gate::before()`، مثل قاعدة مشرف أعلى (`super-admin`)، يعمل قبل كل قدرة ويمكنه منح هذه القدرة أيضًا.

ويمكنك استخدام دالة `closure` بدلًا من ذلك. وهي تتلقّى المستخدم، الذي قد يكون `null`، ومعرّف اللوحة:

```php
use Illuminate\Contracts\Auth\Authenticatable;

'authorize' => fn (?Authenticatable $user, string $panelId): bool => $user?->is_developer ?? false,
```

لا تمنح صلاحية التأليف إلا قيمةُ إرجاع تساوي `true` تمامًا. والقيمة التي تُعَدّ صحيحة (`truthy`) مثل `1` أو `'yes'` ترفض.

!!! warning
    لا يمكن تسلسل (`serialize`) دالة `closure` موجودة في ملف إعدادات، لذلك يفشل `php artisan config:cache` ما دامت الدالة موجودة. استخدم قدرة `gate` في أي تطبيق يخزّن إعداداته مؤقتًا.

`null`، وهي القيمة الافتراضية، ترفض الجميع، وكذلك تفعل أي قيمة أخرى.

## إدارة الإعدادات المسبقة

المشرف الذي يجتاز بوابة التأليف يرى أربعة إجراءات إضافية في صفحة **Manage shortcuts**:

| الإجراء | ما يفعله |
| --- | --- |
| Create preset | إضافة إعداد مسبق جديد وفارغ إلى اللوحة. ولا يكون هو الافتراضي. |
| Clone preset | نسخ إعداد مسبق موجود، بما في ذلك تغييراته |
| Edit preset | وضع اختصار تنقّل على حرف آخر، لكل من يستخدم ذلك الإعداد المسبق |
| Set panel default | اختيار الإعداد المسبق الذي يستخدمه كل مشرف ليس لديه اختيار خاص به. وفي وضع `locked`، هذا يعني الجميع. |

تعديل إعداد مسبق وتغيير الافتراضي كلاهما يغيّر المفاتيح لمشرفين آخرين، لذا يطلب كلا النموذجين تأكيدًا صريحًا قبل الحفظ.

يحتوي الإعداد المسبق على أحرف واختصارات معطّلة، ولا يحتوي أبدًا على روابط مخصّصة. ونموذج **Edit preset** يضبط الأحرف. ولتعطيل اختصار في إعداد مسبق، استدعِ `AuthorSystemMap::editInPlace()` من الكود الخاص بك، وهي تُجري فحوصات الصلاحية والتأكيد نفسها.

اجتياز الـ `gate` في لوحة واحدة لا يمنح أي وصول إلى الإعدادات المسبقة للوحة أخرى.

## أيّ خريطة يستخدمها المشرف

| الحالة | الخريطة المستخدمة |
| --- | --- |
| لا اختيار، ولا إعداد مسبق افتراضي | الاختصارات التلقائية والـ `overlay` |
| لا اختيار، وهناك إعداد مسبق افتراضي مضبوط | الإعداد المسبق الافتراضي |
| اختار إعدادًا مسبقًا (وضع `personal`) | ذلك الإعداد المسبق |
| غيّر اختصارًا (وضع `personal`) | خريطته الشخصية |
| وضع `locked` | اختياره السابق، وإلا فالإعداد المسبق الافتراضي، وإلا فالاختصارات التلقائية |

## كيف تتجمّع التغييرات

يمكن تغيير الاختصار في ثلاثة أماكن: [الـ `overlay`](configuration.md#pinning-and-disabling-shortcuts) في ملف إعداداتك، والخريطة النشطة للمشرف (خريطته الشخصية أو إعداد مسبق)، والروابط الخاصة بالمشرف نفسه بالنسبة إلى الروابط المخصّصة. وتتجمّع على النحو التالي:

- **التعطيل في الـ `overlay` يفوز دائمًا.** لا شيء في أي خريطة يستطيع إعادة ذلك الاختصار.
- **الحرف المخزّن في خريطة المشرف يحلّ محلّ الحرف المثبّت في الـ `overlay`.**
- **الاختصار المعطّل في خريطة المشرف يُزال**، حتى لو ثبّت الـ `overlay` حرفًا له.
- **الاختصار المعطّل يحرّر حرفه** للاختصارات الأخرى في مجمّعه.
- **الحرف المثبّت أو المخزّن يأخذ مفتاحه من حرف تلقائي.** والاختصار الذي كان يملك المفتاح تلقائيًا ينتقل إلى حرفه المتاح التالي.
- **عندما يقع حرفان مثبّتان أو مخزّنان على المفتاح نفسه، يحتفظ به الأول.** يأتي التنقّل قبل الروابط المخصّصة، وإجراءات الترويسة قبل إجراءات الصفوف. ويخسر الاختصار الآخر مفتاحه.
- **الحرف الذي ليس من `a` إلى `z`، أو الذي يكون مفتاحًا محجوزًا في مجمّعه، يُتجاهَل.** ويحتفظ الاختصار بالحرف الذي كان سيحصل عليه لولا ذلك.
