# السماح للمشرفين بالتخصيص

صلاحيتان منفصلتان تتحكمان في من يغيّر المفاتيح:

- **التخصيص الشخصي**، ويُضبط عبر `customization` (`personal` أو `locked`). يسمح للمشرف بتغيير
  مفاتيحه *هو* ولا يمسّ أحدًا غيره.
- **التأليف**، ويُضبط عبر `authorize`. يسمح لشخص ما بتغيير الإعدادات المسبقة المشتركة واختيار الخريطة
  الافتراضية للوحة. وهو مرفوض افتراضيًا، ولا يترتّب تلقائيًا على كون المستخدم مشرفًا.

<a id="personal-and-locked"></a>

## الوضعان الشخصي والمقفل

```php
// config/shortcut-keys.php
'customization' => 'personal', // or 'locked'
```

**`personal`** (الافتراضي) يمنح كل مشرف صفحة "Manage shortcuts"، حيث يستطيع التبديل
بين الإعدادات المسبقة التي تنشرها وتخصيص مفاتيحه الخاصة.

**`locked`** يوقف التعديل الشخصي. يستخدم المشرفون الإعداد المسبق الافتراضي للوحة، الذي يضبطه مشرف
مخوَّل في صفحة الإدارة؛ وإن لم يُضبط أي افتراضي، يحصلون على الأعراف التلقائية. والمشرف الذي
كان لديه اختيار عند تحويل اللوحة إلى `locked`، سواء كان إعدادًا مسبقًا اختاره أو خريطة
خصّصها، يحتفظ به ولا يعود قادرًا على تغييره. وفي وضع `locked` لا تكون صفحة الإدارة متاحة
إلا لمن يجتاز بوابة التأليف.

## صفحة Manage shortcuts

في وضع `personal` يرى كل مشرف هذه الإجراءات:

| الإجراء | ما يفعله |
| --- | --- |
| Change active map | التبديل إلى أحد الإعدادات المسبقة للوحة، أو العودة إلى "Your customizations" |
| Remap a shortcut | وضع اختصار تنقّل على حرف آخر |
| Disable a shortcut | إزالة اختصار تنقّل |
| Reset to default | إسقاط تجاوزك لاختصار واحد |
| Add custom binding | ربط مفتاح بصفحة في التطبيق أو بعنصر في الصفحة (انظر [الروابط المخصّصة](custom-bindings.md)) |

لا تعرض الصفحة إلا أهداف التنقّل. أمّا مفاتيح إجراءات الترويسة والجدول وإجراءات الصفوف فينقلها
مطوّر عبر [الـ `overlay` في الإعدادات](configuration.md#overlay).

الحرف المُعاد تعيينه يُتجاهَل، ويحتفظ الاختصار بحرفه التلقائي، عندما لا يكون ضمن a–z أو يقع على
مفتاح محجوز. انظر [الأحرف المفروضة](configuration.md#forced-letters).

## التفرّع عند أول تعديل

لا يعدّل المشرف أبدًا خريطة مشتركة. أول تعديل له ينسخ الخريطة التي يستخدمها (الإعداد المسبق المختار،
أو الافتراضي للوحة) إلى خريطة خاصة، ويوجّه اختياره إليها، ويخزّن التغيير هناك.
وتبقى الخريطة المشتركة على حالها.

الخريطة الشخصية لا تخزّن إلا الفروق. كل ما لا تذكره يتبع الأعراف الحيّة،
ولهذا يحصل مورد يُضاف الشهر القادم على مفتاح في خريطة خُصّصت اليوم. وهي لا تتبع
الإعداد المسبق الذي نُسخت منه: التعديلات اللاحقة على ذلك الإعداد المسبق لا تصل إليها. "Reset to default" يُسقط
التجاوز، فيعود الاختصار إلى حرفه التلقائي لا إلى حرف الإعداد المسبق. للعودة إلى
إعداد مسبق بالكامل، اختره عبر "Change active map"؛ وتبقى الخريطة الشخصية في القائمة لوقت لاحق.

<a id="the-authoring-gate"></a>

## بوابة التأليف

امنح صلاحية التأليف عبر قدرة `Gate` (موصى به) أو دالة `closure`:

```php
// config/shortcut-keys.php

// the name of an ability you defined
'authorize' => 'manage-shortcut-keys',

// or a closure; needs `use Illuminate\Contracts\Auth\Authenticatable;` at the top of the file
'authorize' => fn (?Authenticatable $user, string $panelId) => $user?->isDeveloper() ?? false,
```

```php
// app/Providers/AppServiceProvider.php
Gate::define('manage-shortcut-keys', fn (User $user, string $panelId) => $user->is_developer);
```

فضّل القدرة. فالـ `closure` في ملف إعدادات لا يمكن تسلسله (`serialize`)، لذا يفشل `php artisan config:cache`
ما دام موجودًا.

- النص يُفحص على شكل `Gate::forUser($user)->allows($ability, $panelId)`. والزائر الذي لا مستخدم له
  يُرفض قبل سؤال البوابة. ودالة رد النداء `Gate::before`، مثل قاعدة المشرف الأعلى (`super-admin`)، تعمل قبل
  كل قدرة ويمكنها منح هذه القدرة أيضًا.
- الـ `closure` يتلقّى المستخدم (وقد يكون null) ومعرّف اللوحة، فيستطيع إعداد واحد أن يجيب لكل لوحة على حدة.
  وحدها القيمة `true` الصارمة تمنح الصلاحية؛ والقيمة المكافئة للصواب مثل `1` أو `'yes'` ترفض.
- `null`، أو أي شيء آخر، يرفض الجميع.

## ما يستطيع المؤلفون فعله

من يجتاز البوابة يحصل على أربعة إجراءات إضافية في صفحة الإدارة:

| الإجراء | ما يفعله |
| --- | --- |
| Create preset | إعداد مسبق جديد وفارغ للوحة. وهو ليس الافتراضي. |
| Clone preset | نسخة من إعداد مسبق موجود، بما في ذلك تجاوزاته |
| Edit preset | وضع اختصار تنقّل على حرف آخر، في مكانه، لكل من يستخدم ذلك الإعداد المسبق |
| Set panel default | الإعداد المسبق الذي يستخدمه كل مشرف لا يملك اختيارًا خاصًا به؛ وفي وضع `locked`، الجميع |

تعديل إعداد مسبق في مكانه وتغيير الافتراضي كلاهما يغيّر المفاتيح لمشرفين آخرين، لذا يتطلّب النموذجان
كلاهما تأشير مربع تأكيد صريح قبل الحفظ. يحمل الإعداد المسبق أحرفًا وتعطيلات، ولا يحمل أبدًا
ربطًا مخصّصًا. يضبط نموذج التعديل الأحرف؛ أمّا التعطيل فيمكن كتابته من الشيفرة عبر
`AuthorSystemMap::editInPlace()`، الذي يجري فحوص البوابة والتأكيد نفسها.

اجتياز البوابة لا يتيح الوصول إلى خرائط لوحة أخرى: كل عملية بحث مقصورة على اللوحة الحالية،
ومعرّف الخريطة القادم من لوحة أخرى يُعامَل على أنه غير موجود.

<a id="how-the-layers-combine"></a>

## كيف تتضافر الطبقات

لكل اختصار، بالترتيب:

1. **الأعراف** تكتشفه. تصل مفاتيح الجدول بمفاتيحها الثابتة؛ وكل ما عداها لا يملك
   حرفًا بعد. وعلى المفاتيح المجرّدة، يبدأ إجراء الترويسة الفوري موقوفًا.
2. **الـ `overlay` في الإعدادات** يثبّت حرفًا (وهذا يشغّل أيضًا إجراء الترويسة الفوري) أو يعطّل
   الاختصار.
3. تُطبَّق **الخريطة الفعّالة** للمشرف: خريطته الشخصية، أو الإعداد المسبق الذي اختاره، أو الافتراضي
   للوحة. الحرف المخزَّن يحلّ محلّ حرف ثبّته الـ `overlay`؛ والتعطيل المخزَّن يوقف
   الاختصار. ولا يستطيع حرف مخزَّن إعادة اختصار عطّله الـ `overlay`.
4. تُضاف **الروابط المخصّصة** للمشرف.
5. تُزال الاختصارات المعطّلة، فتعود أحرفها إلى المجمّع.
6. **تُسنَد الأحرف** في كل مجمّع. توضع الأحرف المثبّتة والمخزّنة أولًا وتأخذ مفتاحها
   من أي اختصار مُسنَد إليه حرف تلقائيًا، فينتقل ذلك الاختصار إلى حرف آخر متاح.

لذا فإن تعطيل الـ `overlay` يفوز دائمًا، بينما يتغلّب الحرف المخزَّن للمشرف على حرف الـ `overlay`. وإذا وقع
حرفان مثبّتان أو مخزّنان على مفتاح واحد، فالأول في ترتيب المجمّع يحتفظ به (التنقّل قبل الروابط
المخصّصة، وإجراءات الترويسة قبل إجراءات الصفوف) ويفقد الآخر مفتاحه.

## من يرى أيّ خريطة

| الحالة | الخريطة المستخدمة |
| --- | --- |
| لا اختيار، ولا افتراضي مضبوط | الأعراف (مع الـ `overlay`) |
| لا اختيار، وافتراضي مضبوط | الافتراضي للوحة |
| اختار إعدادًا مسبقًا (وضع `personal`) | ذلك الإعداد المسبق |
| عدّل مفاتيحه (وضع `personal`) | خريطته الشخصية |
| وضع `locked` | أي اختيار سابق، وإلا فالافتراضي للوحة، وإلا فالأعراف |
